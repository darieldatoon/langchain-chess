# Files

- [Package Map and Dependency Direction](package-map.md) - The Python (uv) and JavaScript (pnpm) packages in langchain-chess, which way dependencies are allowed to point (systemone -> chess, cli and server -> both, web/review -> chess-ui), the runtime HTTP links between them, and a guide to which layer a new feature belongs in.
- [System 1 (SystemOneMiddleware)](system-one.md) - How SystemOneMiddleware ranks the allowed moves with a System 1 classifier (SemIf or Jev via the TypeSafeClassifier-backed GatewayRanker), gates on margin or confidence to either play the top move or suggest a shortlist, runs a seeded tournament when there are more options than one request holds (16 for SemIf), keeps the graph shape with NoSystemOne, and behaves when ranking fails with and without an LLM.
- [Turn lifecycle](turn-lifecycle.md) - How create_chess_agent assembles its fixed middleware stack (including fixed_topology) and how ChessCore plays at most one turn per run, covering command classification, invocation and opened_turn bookkeeping, pending, abandoned, committed and terminal turns, reply parsing, illegal-move retries and resignation, the forced-move shortcut, failed provider calls, atomic finalization, draw claims and ContextBudgetError.
- [Web frontends (apps/web, apps/review, packages/chess-ui)](web-frontends.md) - How the React play UI (apps/web) drives the chess graph through useStream with one thread per game and continues any game from the setup recorded in its thread, how the LangSmith review app (apps/review) reads threads and game_review feedback, and how both share packages/chess-ui as TypeScript source inside a Vite+ pnpm workspace.
